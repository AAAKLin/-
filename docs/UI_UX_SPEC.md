# UI/UX Specification

## Direction
Confirmed overall direction; refine after a runnable version exists.
- Clean, modern, minimal, calm, high clarity.
- Dashboard inspired by a polished “Today Action Center”: clear cards, readable hierarchy, restrained progress indicators, efficient spacing.
- Avoid clutter, excessive gradients/animation, and a giant chat panel.
- Use consistent typography, spacing, borders, icons, and accessible contrast.

## Responsive behavior
- Mobile-first.
- Mobile: bottom navigation with four primary destinations.
- Desktop: sidebar or another clear wide-screen navigation pattern.
- Reflow cards/charts appropriately; do not merely stretch mobile UI.
- Make primary actions easy to reach on a phone.

## Navigation
1. Home — Today Action Center.
2. Training.
3. Diet.
4. My Progress.
Profile/settings and backup/restore can sit within My Progress or a clear secondary settings area.

## Home hierarchy
1. Date and concise status.
2. Today's training task/status.
3. Diet progress (especially calories and protein).
4. Quick record actions.
5. Weight trend/recent progress.
6. One or two concise coach recommendations.

Never imply completion when data is missing; use “Not recorded yet”.

## Training
- Clear planned session and prominent quick log.
- Expand an exercise for actual sets/reps/duration, difficulty, and discomfort where relevant.
- Prefill planned values and distinguish planned from actual.
- Explain plan changes.

## Diet
- Fast add food or saved recipe.
- Easy portion adjustments.
- Label uncertain nutrition values.
- Separate suggested meals from actual intake.
- Allow food/recipe data correction.

## Progress and accessibility
- Emphasize trends, not isolated fluctuations.
- Avoid shaming/guilt-based language.
- Clear empty states and validation errors.
- Practical mobile touch targets, keyboard access where feasible.
- Do not use color as the only status signal.

## Review
Launch and inspect mobile/desktop layouts if the environment supports it. Otherwise report the limitation and tell the user how to review.
